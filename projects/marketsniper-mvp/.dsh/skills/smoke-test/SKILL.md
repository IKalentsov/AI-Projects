# Smoke Test

Smoke test — это не полный тест-план. Это быстрый ответ на вопрос:
**«после изменений система всё ещё жива на базовом уровне?»**

## Когда использовать

- Перед объявлением задачи завершённой.
- После изменений в инфраструктуре (compose, Dockerfile, конфиги, миграции).
- После слияния крупной ветки.
- После подъёма окружения на чистой машине.

## Минимальный чек-лист (наш проект)

**Инфраструктура**
- [ ] `docker compose -f docker/compose/compose.infra.yaml up -d` поднимает postgres и redis без ошибок.
- [ ] `docker compose ps` — все контейнеры `healthy`.

**Бэкенд**
- [ ] `GET /health/live` → 200.
- [ ] `GET /health/ready` → 200 и в ответе видно проверки БД и Redis.
- [ ] Swagger/Scalar открывается, схема генерируется без ошибок.
- [ ] Миграции применились (или `dotnet ef migrations list` показывает актуальные).

**Фронтенд**
- [ ] Приложение открывается по своему URL, нет ошибок в консоли браузера.
- [ ] 1–3 ключевых пользовательских сценария проходят целиком (не только «страница открылась»).
- [ ] Есть корректные состояния: загрузка, пустой результат, ошибка.

**Сквозной сценарий (главный для проекта)**
- [ ] Пользователь вводит поисковый запрос → получает список результатов → открывает карточку
      товара со ссылкой на маркетплейс.

## Типичные ошибки

- Завершать задачу без проверки («тесты зелёные — значит работает»).
- Проверять только свой слой и забыть про соседний.
- Проверять на закэшированных данных и не заметить, что реальный путь сломан.
- Считать «контейнер запущен» равным «сервис отвечает».

## Как оформлять результат

Коротко: что поднимал, что проверял, что получил. Если что-то не проверялось —
честно указать, что именно и почему.
