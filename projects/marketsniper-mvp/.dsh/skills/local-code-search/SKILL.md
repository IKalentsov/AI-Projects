# Local Code Search

Цель — не читать проект целиком вручную, а быстро найти место, где уже живёт нужная логика
(или где её правильно разместить).

## Когда использовать

- Не знаешь точное имя файла/класса/функции.
- Нужно понять, как похожая задача уже решалась в этом проекте.
- Проверка перед тем, как писать новое: не дублируем ли существующее.

## Подход

1. **Ищи по смыслу**: ключевые доменные слова (например `product`, `price`, `marketplace`,
   `supplier`, `search`), затем синонимы и части слов.
2. Ищи в трёх плоскостях: имя файла/путь (glob), содержимое (grep), структура слоя.
3. Читай 1–3 самых релевантных результата **целиком**, а не по кусочкам.
4. Уточняй запрос по мере понимания (от общего слова к конкретному типу).
5. Только после этого решай, где менять код.

## Полезные маршруты в этом репозитории

- Домен и инварианты → `backend/src/MarketSniper.Domain/`
- Use cases и валидаторы → `backend/src/MarketSniper.Core/`
- Контракты API → `backend/src/MarketSniper.Contracts/`
- Доступ к данным → `backend/src/MarketSniper.Infrastructure.Postgres/`
- Точки входа и middleware → `backend/src/MarketSniper.Web/`
- UI-фичи → `frontend/apps/web/src/features/`
- Общие компоненты и утилиты → `frontend/packages/`
- Правила и соглашения → `AGENTS.md`, `docs/`, `.dsh/skills/`

## Типичные ошибки

- Читать весь проект подряд без стратегии.
- Искать только точным именем и делать вывод «такого нет».
- Дублировать существующую логику, не проверив проект.
- Игнорировать `ARCHITECTURE.md` при поиске «где это должно лежать».

## Чек-лист

- [ ] Не читаю проект подряд без плана поиска.
- [ ] Если точного имени нет — ищу по смыслу и синонимам.
- [ ] Найденный участок релевантен, и понятно почему.
- [ ] Проверил, что не дублирую существующее.
