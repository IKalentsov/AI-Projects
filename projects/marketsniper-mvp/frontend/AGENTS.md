## 2. Структура монорепо (pnpm)

```
frontend/
├── apps/web/                 # SPA-приложение (поиск, результаты, кабинет)
├── apps/landing/             # лендинг — появится отдельным приложением (SSG/SSR)
├── packages/ui/              # дизайн-система: компоненты shadcn/ui, токены, стили
├── packages/api-client/      # сгенерированный клиент + query-хуки
├── packages/shared/          # типы, утилиты, константы, общие для приложений
├── packages/eslint-config/   # общие конфиги линтера
├── packages/tsconfig/        # базовые tsconfig
├── pnpm-workspace.yaml
└── package.json              # корневые скрипты и версии
```

Слои внутри `apps/web/src` и направление зависимостей — `docs/frontend/project-structure.md`.

## 3. Размещение кода

- `app/` — провайдеры, роутер, ErrorBoundary. Логики здесь минимум.
- `routes/` — тонкий слой маршрутов: собрать фичи и сущности в экран, без бизнес-логики.
- `features/` — одна папка = одна бизнес-возможность (`offer-search`, `offer-filters`).
- `entities/` — доменные сущности (`offer`, `seller`, `product`), только переиспользуемое.
- `shared/` — UI-кит, утилиты, конфиг, тестовые утилиты; не знает о фичах.
- Зависимости только в одну сторону: `shared → entities → features → routes/app`.
- **Импорт между соседними `features/*` запрещён.** Композиция — на уровне `routes/`.
  Проверяется правилом `import-x/no-restricted-paths` (конфиг — в `docs/frontend/project-structure.md`).
- Barrel-файлы (`index.ts`, реэкспортирующий всё подряд) запрещены: ломают tree-shaking.
  Исключение — `features/<name>/index.ts` как Public API фичи (только явные экспорты).

## 4. Данные

- Серверные данные — **только** TanStack Query. Никаких `useEffect` + `fetch` и «своих» кэшей.
- Ключи запросов — через фабрику ключей фичи; ключ включает все параметры запроса.
- `queryFn` живёт в `features/<name>/api/`; компонент вызывает хук фичи, а не клиент напрямую.
- Мутация обязана инвалидировать затронутые ключи (`onSettled` → `invalidateQueries`).
- Клиентское состояние — Zustand (UI-состояние, черновики фильтров до применения).
- Состояние поиска (запрос, фильтры, сортировка, страница) — **в URL** (nuqs):
  ссылка на результаты должна шариться и переживать перезагрузку.
- Правила, примеры и запреты — `docs/frontend/data-and-state.md`.

## 5. Формы

- Только react-hook-form + zod через `zodResolver`. `useState` на каждое поле — запрещён.
- Схема zod — единственный источник типа формы (`z.infer<typeof schema>`).
- Сообщения об ошибках — по-русски, из схемы; тексты не дублируются в разметке.
- Ответ API валидируется zod-схемой до попадания в UI.

## 6. API-клиент

- Клиент генерируется из OpenAPI-схемы backend (`orval`): файлы в
  `packages/api-client/src/generated/**`.
- Сгенерированные файлы **не редактируются руками** и не импортируются в UI напрямую —
  только через хуки фичи.
- Схема обновилась на backend — в том же MR регенерируется клиент; CI проверяет,
  что сгенерированный код соответствует схеме.

## 7. Обязательные состояния экрана

Каждый экран с асинхронными данными реализует **четыре** состояния, даже если кажется,
что «пусто не бывает»:

| Состояние | Требование |
|-----------|-----------|
| Загрузка | Скелетон/спиннер на месте контента (без прыжков вёрстки); повторный запрос — не сбрасывает экран |
| Пусто | Текст «ничего не найдено» + что изменить в запросе; без пустого белого экрана |
| Ошибка | Понятный текст + кнопка «Повторить»; технические детали — в лог, не пользователю |
| Успех | Данные + пустой/частичный результат обрабатывается отдельно от ошибки |

Плюс сквозные состояния: «нет доступа» (когда появится авторизация) и «частичная загрузка»
(часть маркетплейсов не ответила — показываем то, что есть, с пометкой).

## 8. Доступность (WCAG 2.2 AA — обязательно)

- Целевой уровень — AA; проверяется чек-листом из `docs/frontend/quality.md`.
- Семантика: `<button>` для действий, `<a>` для переходов, `<label>` для полей.
- Клавиатура: всё интерактивное достижимо Tab, фокус видим (`:focus-visible`, ring-токен).
- Формы: `aria-invalid` и `aria-describedby` на ошибках; ошибка связана с полем.
- Асинхронный результат поиска: `aria-live="polite"` на контейнере результатов.
- Изображения — `alt` (декоративные — `alt=""`); иконки-кнопки — `aria-label`.
- Интерактивные элементы — не меньше 24×24 CSS px ([WCAG 2.2](https://www.w3.org/TR/WCAG22/)).

## 9. Запрещено

- CSS-файлы на компонент, inline-стили (`style={{...}}`), прямые манипуляции с DOM;
  стилизация — только Tailwind-утилиты и токены темы.
- `any`, `@ts-ignore`, `@ts-expect-error` без комментария-обоснования, `as unknown as`.
- `!important`, хардкод цветов/размеров вместо токенов.
- Дефолтные экспорты, кроме случаев, требуемых инструментом (lazy-маршруты, конфиги).
- Barrel-файлы, импорт из `features/*` в `features/*`, импорт из `routes/` внутрь фич.
- Прямые `fetch`/`axios` в компонентах и хуках фич.
- `moment.js` (используем `Intl` или `date-fns`), `lodash` целиком (точечные импорты).
- Хранение токенов и персональных данных в `localStorage` без согласования (см. `docs/adr/0007-auth-deferred.md`).
- Добавление зависимости без обоснования и проверки лицензии/актуальности версии.
- Тесты на реализацию (обращения к внутреннему состоянию, снапшоты разметки).

## 10. Команды

```bash
cd frontend
pnpm install
pnpm dev            # запуск apps/web (Vite)
pnpm lint           # ESLint по всем пакетам
pnpm typecheck      # tsc --noEmit во всех пакетах
pnpm test           # Vitest (unit + component + integration)
pnpm test:coverage  # покрытие
pnpm test:e2e       # Playwright (нужен поднятый стенд)
pnpm build          # сборка приложения
pnpm api:generate   # генерация клиента из OpenAPI-схемы backend
```

## 11. Определение готовности (фронт)

Корневой DoD (`AGENTS.md`, §9) плюс специфика:

1. `pnpm typecheck`, `pnpm lint` — без ошибок и предупреждений.
2. `pnpm test` — все тесты зелёные; новый функционал покрыт тестами нужного уровня
   (`docs/frontend/testing.md`).
3. `pnpm build` — сборка проходит, размер бандла в бюджете (`docs/frontend/quality.md`).
4. Экран реализует все обязательные состояния (§7) и проходит a11y-чек-лист (§8).
5. Ссылка на результаты поиска шарится: состояние воспроизводится из URL.
6. Отсутствуют запреты из §9; новых зависимостей нет либо они согласованы.
7. Обновлены `docs/frontend/*` и OpenAPI-производные артефакты, если менялись версии,
   структура или контракт.

## 12. Красные линии

- Отключать правило линтера/типов вместо исправления кода.
- Коммитить `packages/api-client/src/generated/**`, расходящийся с OpenAPI-схемой backend.
- Дублировать серверные данные в Zustand или в `useState` «для удобства».
- Обходить типы (`any`, `@ts-ignore`) и «временно» ломать слои (`features` → `features`).
- Править сгенерированный код руками.
- Реализовывать состояние экрана без обработки пустого результата и ошибки.
