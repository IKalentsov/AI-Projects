# docs — документация проекта

Правила работы — в корневом `AGENTS.md`. Единый источник правды по архитектуре — `ARCHITECTURE.md`
в корне репозитория. Здесь — детализация, решения и предметная область.

## Карта документации

```
docs/
├── README.md                     # этот файл: что где лежит
├── ../WORKFLOW.md                # процесс: цикл, постановки, ревью, DoD, fitness (в корне проекта)
├── architecture/
│   ├── clean-architecture.md     # слои, зависимости, правила размещения кода, architecture fitness
│   ├── infrastructure-docker.md  # контейнеры, сеть, тома, окружения
│   ├── testing-strategy.md       # пирамида тестов, инструменты, требования
│   └── ci-cd.md                  # пайплайн: стадии, кэш, качество, деплой
├── backend/
│   ├── coding-standards.md       # соглашения C#-кода и структуры файлов
│   ├── data-access.md            # EF Core, Dapper, миграции, индексы
│   └── api-conventions.md        # версионирование, ошибки, пагинация, OpenAPI
├── frontend/
│   ├── stack.md                  # стек и версии, обоснование выбора
│   ├── project-structure.md      # структура приложения и правила размещения
│   ├── data-and-state.md         # TanStack Query, состояние, формы, API-клиент
│   ├── testing.md                # Vitest, RTL, MSW, Playwright
│   └── quality.md                # ESLint, Prettier, TypeScript strict, a11y
├── domain/
│   ├── overview.md               # что за продукт, сценарии, открытые вопросы
│   └── glossary.md               # глоссарий (рус ↔ англ)
└── adr/
    ├── README.md                 # что такое ADR и как их вести
    └── NNNN-*.md                 # принятые решения
```

## Правила ведения

1. **Не дублировать `ARCHITECTURE.md`**: структуру, стек и версии держим в одном месте.
   Здесь — пояснения, примеры, процедуры.
2. Любое архитектурное решение оформляется ADR (см. `docs/adr/README.md`).
3. Изменения документации вносит архитектор; исполнитель читает (см. `AGENTS.md` §2).
4. Документ без владельца и даты обновления — плохой документ: в каждом файле есть шапка
   или строка «Последнее обновление».
5. Устаревшее не удаляем молча: либо актуализируем, либо помечаем `Статус: устарело`
   с указанием, что вместо этого читать.
