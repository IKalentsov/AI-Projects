## Форматирование и анализаторы

| Инструмент | Файл | Что задаёт |
|------------|------|-----------|
| Форматирование и стиль | `.editorconfig` (корень) | отступы, переносы, стиль объявлений, именование |
| Уровни анализаторов | `backend/.globalconfig` | какие правила — ошибка/предупреждение/выключено |
| Свойства сборки | `backend/Directory.Build.props` | TFM, `TreatWarningsAsErrors`, набор анализаторов |
| Версии пакетов | `backend/Directory.Packages.props` | центральные версии |

Анализаторы: Roslynator, Meziantou, AsyncFixer, SonarAnalyzer + встроенные CAxxxx при
`AnalysisMode=All`. Любое предупреждение — ошибка сборки. Отключение правила возможно только
через архитектора и только с обоснованием в `.globalconfig`.

```bash
cd backend
dotnet format                       # автоисправление форматирования
dotnet format --verify-no-changes   # проверка в CI
dotnet build                        # анализаторы + предупреждения как ошибки
```

## Именование

| Элемент | Правило | Пример |
|---------|---------|--------|
| Проект | `MarketSniper.<Слой>` | `MarketSniper.Core` |
| Сущность | существительное, ед. ч. | `Offer`, `Seller` |
| Value Object | без суффиксов | `Price`, `TrustScore` |
| DTO | суффикс `Dto` | `SearchOffersRequestDto` |
| Обработчик | суффикс `Handler` | `SearchOffersQueryHandler` |
| Валидатор | суффикс `Validator` | `SearchOffersValidator` |
| Интерфейс | префикс `I` | `IOffersRepository` |
| Приватное поле | `_camelCase` | `_logger` |
| Асинхронный метод | суффикс `Async` | `GetOffersAsync` |
| Константа | `PascalCase` | `MaxOffersPerPage` |
| Тест | `Метод_Сценарий_Ожидание` | `Create_WithNegativePrice_ReturnsError` |

## Структура файлов

- Один публичный тип — один файл (исключение: тесно связанные `Command` + `Handler`).
- Порядок членов: константы → поля → конструктор → публичные методы → приватные методы.
- `file-scoped namespace`; `using` — вне namespace, системные первыми.
- Длина файла — до ~300 строк; больше — сигнал разделить ответственность.
- Папка фичи в `Core` называется по домену (`Offers`, `Sellers`), а не по слою.

## Правила, которые проверяются ревью

1. **Явность важнее краткости**: понятное имя лучше короткого, ранний выход лучше вложенности.
2. **Никаких magic strings/numbers**: константы, `nameof`, VO, конфигурация.
3. **Иммутабельность по умолчанию**: `record`, `init`, `readonly` там, где это возможно.
4. **Минимум публичной поверхности**: `internal` для того, что не является контрактом.
5. **Null-forgiving (`!`) запрещён** без комментария, объясняющего инвариант.
6. **Комментарии — про «почему»**, XML-doc — на публичных контрактах (`Contracts`, публичные API Core).
7. **Один метод — одна ответственность**; больше 40 строк — повод разделить.
8. **Никаких `TODO` без задачи** в `ai-tasks/` или ссылки на неё.

## Работа с пакетами

1. Проверить лицензию (только MIT/Apache-2.0/BSD-подобные, без платных и trial).
2. Добавить версию в `backend/Directory.Packages.props` с комментарием «зачем».
3. В `.csproj` — `<PackageReference Include="..." />` без версии.
4. Обновить `packages.lock.json` (`dotnet restore`).
5. Если пакет архитектурно значим (БД, брокер, аутентификация) — сначала ADR.

## Definition of Done для C#-задачи

- [ ] `dotnet build` — без предупреждений.
- [ ] `dotnet test` — все тесты зелёные.
- [ ] `dotnet format --verify-no-changes` — чисто.
- [ ] Новый код покрыт тестами нужного уровня.
- [ ] Публичные контракты задокументированы XML-doc (если это `Contracts`/публичный API).
- [ ] Архитектурные тесты не нарушены (слои, именование).
