# ADR — Architecture Decision Records

ADR фиксирует **принятое решение** и его обоснование: контекст → варианты → решение →
последствия. Цель — чтобы через полгода было понятно не только «как», но и «почему так».

## Формат

Файл: `docs/adr/NNNN-<короткое-название>.md`, номер — сквозной, без пропусков.

```markdown
# NNNN. <Название решения>

- **Статус:** предложено | принято | заменено (NNNN) | устарело
- **Дата:** ГГГГ-ММ-ДД
- **Контекст:** ...
- **Решение:** ...
- **Альтернативы:** ...
- **Последствия:** что становится проще, что сложнее, какие ограничения принимаем.
```

## Правила

- Одно решение — один ADR. Не «переписывать» старый ADR: изменилось решение — новый ADR
  со статусом «принято», а старый помечается «заменено (NNNN)».
- ADR пишет архитектор; изменение статуса — тоже он.
- Если решение меняет структуру/контракты/стек — синхронно обновляется `ARCHITECTURE.md`.
- ADR не заменяет документацию: он объясняет **почему**, а не **как**.
