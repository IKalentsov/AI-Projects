# ADR 0003. Фронтенд: React + Vite SPA

- **Статус:** принято
- **Дата:** 2026-09-10

## Контекст

Продукту нужны два разных пользовательских входа: приложение (поиск, результаты, карточка
предложения, личный кабинет) и в перспективе лендинг с требованием к SEO. Backend — отдельный
.NET 10 REST API; контракт — OpenAPI-схема. Команда — один разработчик с AI-агентами,
всё окружение — в Docker (см. `docs/adr/0006-container-first.md`), контейнер фронтенда
раздаёт статику через прокси (`docker/README.md`).

Ограничения: open source без платных лицензий, минимум собственной инфраструктуры,
предсказуемая сборка в CI, единый дизайн-слой для приложения и лендинга.

## Решение

1. **SPA на Vite 8 + React 19.3 + TypeScript 6.0.x**, маршрутизация — **React Router 8**
   (data router, ленивые маршруты), сборка — статические файлы.
2. **pnpm-монорепо**: `apps/web` (SPA), `packages/{ui,api-client,shared,eslint-config,tsconfig}`.
   Лендинг появится отдельным приложением `apps/landing` и переиспользует `packages/ui`
   и `packages/api-client`.
3. **SSR/SSG для лендинга — отдельным приложением позже** (кандидаты: Next.js 16 или
   TanStack Start 1.x). SPA при этом не переписывается.
4. Версии и обоснование — `docs/frontend/stack.md`; правила кода — `frontend/AGENTS.md`.

## Альтернативы

1. **Next.js 16 (App Router) для всего**: даёт SSR/RSC, метаданные и SEO «из коробки»,
   но требует собственного Node-рантайма, дублирует серверные возможности backend и сильнее
   связывает фронтенд с моделью Vercel. Для SPA с отдельным API это лишний слой.
2. **TanStack Start 1.x**: type-safe роутинг, SSR/SSG, сборка на том же Vite (переиспользуем
   плагины). Отклонено на этапе MVP: меньше рецептов, примеров и готовых решений;
   вариант остаётся основным кандидатом под SSR-лендинг.
3. **CRA-подобное решение на webpack**: Create React App не поддерживается, webpack медленнее
   Rolldown, конфигурация сложнее. Отклонено.
4. **Remix / React Router framework mode с сервером**: серверный рантайм нужен только ради
   метаданных, а лендинг — единственное место, где они требуются. Отложено вместе с лендингом.

## Последствия

**Проще:** быстрый dev-цикл и сборка (Vite 8 на Rolldown); раздача статики любым сервером
и через Caddy в контейнере; независимость от backend-рантайма; лендинг и SPA делят один
дизайн-слой и один сгенерированный API-клиент; e2e-тесты не требуют серверного рендера.

**Сложнее:** SEO и метаданные для SPA придётся решать отдельно (лендинг отдельным
приложением, pre-render для публичных страниц); стартовый HTML пустой — нужны качественные
скелетоны; монорепо требует дисциплины версий и общего тулинга.

**Ограничения, которые принимаем:**

- TypeScript пинится на 6.0.x до поддержки TypeScript 7 в typescript-eslint
  (`docs/frontend/stack.md`, §4).
- Лендинг — отдельное приложение; попытка «прикрутить SSR» к `apps/web` — новое решение,
  а не самодеятельность.
- Общие пакеты версионируются вместе с приложениями (монорепо, `docs/adr/0001-monorepo.md`).
