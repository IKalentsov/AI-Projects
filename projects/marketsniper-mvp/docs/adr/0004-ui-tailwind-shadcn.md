# ADR 0004. UI: Tailwind CSS 4.3 + shadcn/ui

- **Статус:** принято
- **Дата:** 2026-09-10

## Контекст

Нужен UI-слой для SPA (поиск, результаты, карточки предложений, формы) и в перспективе —
для лендинга. Требования: open source без платных подписок; тёмная тема; доступность;
быстрый старт без собственной дизайн-системы «с нуля»; единый вид приложения и лендинга;
возможность менять компоненты под наш домен (карточка предложения, бейдж надёжности продавца,
сравнение цен).

## Решение

1. **Tailwind CSS 4.3** с CSS-first конфигурацией: дизайн-токены описываются в `@theme`
   в `packages/ui/src/styles/globals.css` и доступны как CSS-переменные; сборка — плагином
   `@tailwindcss/vite` ([Tailwind v4](https://tailwindcss.com/blog/tailwindcss-v4)).
2. **shadcn/ui**: компоненты **копируются в репозиторий** (`packages/ui/src/components`)
   через CLI и реестр ([ui.shadcn.com/docs/cli](https://ui.shadcn.com/docs/cli),
   [registry](https://ui.shadcn.com/docs/registry)); доступность обеспечивают примитивы
   (Base UI / Radix), поверх которых построены компоненты.
3. Темы: семантические CSS-переменные (`--background`, `--foreground`, `--primary`, …)
   в `:root` и `.dark`; переключение — класс `dark` на `<html>`.
4. Правила использования — `frontend/AGENTS.md` (§9) и `docs/frontend/quality.md`.

## Альтернативы

1. **MUI** ([@mui/material](https://www.npmjs.com/package/@mui/material)) — зрелая библиотека
   с богатым набором компонентов и enterprise-таблицами. Отклонено: собственный рантайм
   и тема (Emotion), конкуренция с Tailwind, заметный размер бандла; кастомизация под наш
   домен сложнее, чем правка собственного кода компонента.
2. **Ant Design** ([antd](https://www.npmjs.com/package/antd)) — сильные таблицы и формы,
   но узнаваемый «админский» вид, тяжёлая тема и CSS-in-JS; для потребительского поиска
   избыточно.
3. **Mantine** ([@mantine/core](https://www.npmjs.com/package/@mantine/core)) — хорошая
   документация и DX, но это снова зависимость со своим рантаймом и своим слоем стилей.
4. **Chakra UI** ([@chakra-ui/react](https://www.npmjs.com/package/@chakra-ui/react)) —
   удобные примитивы, но пропс-ориентированная стилизация конфликтует с Tailwind-подходом.
5. **Собственная дизайн-система с нуля** — полный контроль, но недоступность (фокус, ARIA,
   клавиатура) придётся реализовывать и тестировать самостоятельно; для MVP слишком дорого.
6. **Готовый платный UI-кит** (Tailwind Plus и аналоги) — отклонено: правило проекта
   «только open source, без платных подписок».

## Последствия

**Проще:** полный контроль над разметкой и поведением компонентов (код в нашем репозитории);
нет привязки к мажорным версиям UI-библиотеки; тёмная тема и токены — на уровне CSS;
доступность «из коробки» за счёт примитивов; одинаковая база для приложения и лендинга;
лицензионных ограничений нет (MIT-совместимые компоненты).

**Сложнее:** компоненты нужно поддерживать самим — обновление shadcn-компонентов делается
вручную (перегенерация + перенос наших правок); при росте числа компонентов нужен Storybook
и правила ревью UI; нельзя «просто обновить пакет», чтобы получить новые возможности.

**Ограничения, которые принимаем:**

- Только Tailwind-утилиты и токены темы в разметке: inline-стили и CSS-файлы на компонент
  запрещены (`frontend/AGENTS.md`).
- Любой новый компонент сначала ищется в реестре shadcn; «свой с нуля» — только с обоснованием.
- Обновление базовых компонентов фиксируется в `docs/frontend/stack.md` и проверяется
  тестами и a11y-чек-листом.
