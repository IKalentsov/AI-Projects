# AGENTS.md — MarketSniperMVP

> Правила работы в этом репозитории для AI-агента и людей.
>
> **Иерархия инструкций**: `~/.dsh/AGENTS.md` (глобальные правила харнесса, включая git-ограничения
> и работу с референс-репозиториями) → **этот файл** (правила проекта) → `backend/AGENTS.md` и
> `frontend/AGENTS.md` (специфика стека). Более конкретный файл имеет приоритет.
> Ни один из них не отменяет прямые указания пользователя.
>
> **Другие источники правды:**
> - `WORKFLOW.md` — процесс: цикл задачи, постановки, ревью и его закрытие, Definition of Done,
>   architecture fitness, git-конвенции. Читать, когда задача касается процесса.
> - `ARCHITECTURE.md` — что и как устроено. Не дублировать его содержимое в других файлах.

## 1. Проект

**MarketSniper (MVP)** — сервис поиска проверенных поставщиков и товаров на маркетплейсах.

Пользователь вводит запрос («хочу найти грецкие орехи») → система собирает предложения
с маркетплейсов (Ozon, Яндекс.Маркет, Wildberries, ВкусВилл и др.), проверяет их по
критериям качества/надёжности (в перспективе — требования РосКонтроля/ГОСТ: чистота,
обработка, условия хранения) и выдаёт только актуальные релевантные результаты со ссылками.

- **Статус**: этап закладки правил и структуры. Код проекта ещё не создан — см. `ARCHITECTURE.md`.
- **Расположение**: монорепозиторий `AI-Projects` (`git@github.com:IKalentsov/AI-Projects.git`),
  каталог `projects/marketsniper-mvp/`. Рабочая ветка — `develop`.
- **Эталонный проект**: `H:\CSharp\SachkovTech\DirectoryService` — референс по подходам,
  структуре и качеству кода. При сомнениях сверяемся с ним. Пользователь сообщает,
  когда в референсе что-то изменилось — тогда адаптируем подходы здесь.
- **Git — зона пользователя**: агент не выполняет операции, меняющие состояние репозитория
  (§10). Ветку создаёт пользователь, push делает пользователь.
- **Внешние референсы**: организация `sachkov-inside` на GitHub (правила, стандарты кода,
  харнесс, процесс) — обращаться только с разрешения пользователя; порядок — §12
  глобальных правил `~/.dsh/AGENTS.md`.
- **Домен и открытые вопросы**: `docs/domain/`.

## 3. Язык и общение

- Общение с пользователем — **русский**.
- Код: идентификаторы, имена файлов/таблиц/эндпоинтов — **английский**.
- Комментарии, XML-документация, `.md` — **русский**.
- Отвечать по делу, без воды. Неуверенное утверждение помечать как неуверенное и проверять
  (код, документация, официальные источники), а не выдавать за факт.
- Пользователь слабо знает фронтенд: решения по React/UI объяснять кратко и по-русски,
  с обоснованием «почему так принято в индустрии».

## 4. Стек (кратко)

Полные версии, обоснования и структура — в `ARCHITECTURE.md` и `backend/Directory.Packages.props`.

| Слой | Технологии |
|------|-----------|
| Backend | .NET 10, C# (последняя версия), ASP.NET Core, Clean Architecture (5 слоёв), CSharpFunctionalExtensions (Result), FluentValidation, Scalar (OpenAPI) |
| Данные | PostgreSQL 18 (EF Core + Dapper), Redis (кэш, rate-limit, очереди) |
| Frontend | React (последняя версия) + TypeScript, Vite, Tailwind CSS, shadcn/ui, TanStack Query, React Router, react-hook-form + zod |
| Инфраструктура | Docker + Docker Compose (всё в контейнерах: backend, frontend, БД, Redis), Caddy как reverse-proxy, GitLab CI, SonarQube (Community) |
| Тесты | xUnit v3 (unit / integration / architecture), Testcontainers; фронт: Vitest + React Testing Library + MSW + Playwright |
| Наблюдаемость | Serilog + OpenTelemetry (единый OTLP-транспорт); dev — Aspire Dashboard (MIT), Seq — опционально |

Правило: **новые зависимости только open source**, без платных подписок и триал-лицензий.
Перед добавлением пакета — проверить лицензию и актуальность версии.

## 7. Красные линии (что запрещено)

- Коммитить секреты, токены, пароли, `.env`, дампы БД и реальные данные маркетплейсов.
- Выполнять git-операции вместо пользователя (§10).
- Менять `ARCHITECTURE.md`, `AGENTS.md`, `WORKFLOW.md`, `docs/`, `ai-tasks/` исполнителю — только read.
- Отключать анализаторы, правила линтера, тесты или `TreatWarningsAsErrors` без согласования.
- Писать CSS-файлы вручную и подключать сторонние UI-киты «на глаз» — только Tailwind +
  компоненты библиотеки (см. `docs/frontend/`).
- Использовать `any`, `@ts-ignore`, `as unknown as` для обхода типов.
- Хардкодить URL, ключи, лимиты и тексты ошибок — только конфиг/константы.
- Пушить напрямую в `main`/`master` и делать force-push в защищённые ветки.
- Добавлять платные/лицензионно-ограниченные зависимости.
- Расширять объём микро-задачи «заодно» — см. `WORKFLOW.md` §3 (одно условие остановки).
- Делать «на будущее» абстракции, которые не нужны текущей задаче (YAGNI).

## 9. Команды (целевые)

Команды появятся вместе с кодом; схема фиксируется заранее, чтобы правила и CI совпадали.

```bash
# Backend (из backend/)
dotnet restore --locked-mode
dotnet build --no-restore
dotnet test --solution MarketSniper.slnx -c Debug     # тесты — через Microsoft.Testing.Platform
dotnet format --verify-no-changes

# Frontend (из frontend/)
pnpm install --frozen-lockfile
pnpm lint && pnpm typecheck
pnpm test && pnpm test:e2e
pnpm build

# Инфраструктура (из корня; .env создаётся из шаблона)
cp .env.example .env
docker compose -f docker/compose/compose.infra.yaml --env-file .env up -d
docker compose -f docker/compose/compose.yaml --env-file .env --profile observability up -d
```

Полный стек в контейнерах — `docker compose -f docker/compose/compose.yaml --env-file .env
--profile app up -d --build`. Подробности — `docker/README.md` и
`docs/architecture/infrastructure-docker.md`.

## 10. Git — зона пользователя

- **Все git-операции выполняет пользователь.** Агенту запрещено запускать `clone`, `init`,
  `add`, `commit`, `branch`, `checkout`, `switch`, `merge`, `rebase`, `push`, `pull`, `stash`,
  `remote`, `tag` — ни в проекте, ни в родительском репозитории `AI-Projects`.
  Разрешено только чтение: `git status`, `git diff`, `git log`, `git show` — для ревью.
- **Рабочий цикл**: пользователь даёт задачу и создаёт ветку → агент выполняет работу →
  пользователь проверяет и пушит. Сам коммит делает пользователь: агент не запускает
  ни `add`, ни `commit`, ни `push`.
- **Помощь с сообщением коммита**: после подтверждения приёмки агент может **предложить текст**
  коммита (по фактическому диффу, не по памяти) — порядок и формат в `WORKFLOW.md` §9.
- Ветки и шаблон MR — `WORKFLOW.md` §9.

## 11. Работа с агентом в этой среде (DSH)

- `AGENTS.md` и `.dsh/skills/**` читаются харнессом автоматически; вложенные `AGENTS.md`
  подхватываются при работе в соответствующем каталоге.
- Длинные задачи ведём через список шагов (`todo_write`), независимые исследования —
  через фоновых субагентов; результаты субагентов проверяем по коду, а не по пересказу.
- Долгие команды (сборка, docker, тесты) запускаем фоном и не блокируемся на них.
- Песочница файловой системы ограничивает запись рабочей папкой проекта: файлы вне неё
  (например `~/.dsh/AGENTS.md` или корень `AI-Projects`) требуют отдельного подтверждения.
