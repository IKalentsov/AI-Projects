# Active Context

## Текущее состояние
QwenAnswers — консольный чат-клиент с AI-моделью через OpenAI-совместимый API.
Проект разбит на классы (Config / Chat / ConsoleAbstraction) и покрыт тестами.

## Что сделано
- Настройки читаются из `.env`; `.env` не попадает в git, есть шаблон `.env-public`
- `.env` копируется в output при сборке — оттуда его читает `Program.cs`
- Валидация настроек вынесена из `Program.cs` в `Config/AppConfigValidator` и покрыта тестами
- Имена ключей `.env` вынесены в `Config/EnvKeys` (единый источник правды для кода, шаблона, README и тестов)
- Проверка схемы `AI_ENDPOINT` (`http://` / `https://`) — ловит опечатку «забыл схему»
- Сборка боевых компонентов вынесена в `Chat/ChatSessionFactory` (тестируется тот же путь, что и в приложении)
- Исправлено дублирование вопроса пользователя в истории (`ChatSession`)
- Исправлен `ChatLoop`: свежий токен отмены на каждый запрос (после Esc чат больше не ломался),
  выход по концу ввода (раньше был бесконечный цикл), устойчивость к перенаправленному вводу
- Удалён неиспользуемый Win32-код `ConsoleInputControl`; убраны неиспользуемые пакеты Configuration
- Тесты: unit / integration / architecture, категории Readiness и Live

## Архитектура
Однопоточная, последовательная. Пока AI обрабатывает запрос — консоль заблокирована (`await`).
История меняется только после успешного ответа модели: неудачный запрос в неё не попадает.

## Стек
- .NET 10.0, C# latest
- Microsoft.Extensions.AI + OpenAI SDK
- Простой парсер `.env` без внешних зависимостей
- Тесты: xUnit v2 + Moq + FluentAssertions

## Известные ограничения
- Лимит `AI_MAX_HISTORY_MESSAGES` считает реплики (пары «вопрос + ответ»), а не отдельные сообщения —
  имя ключа осталось историческим, поведение задокументировано в README
- Парсер `.env` не поддерживает префикс `export` и инлайновые комментарии после значения
- `IEnvConfigLoader` используется только как контракт: приложение работает с конкретным `EnvConfigLoader`
