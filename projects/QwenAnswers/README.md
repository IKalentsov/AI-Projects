# QwenAnswers

Консольное приложение для чата с AI-моделью через OpenAI-совместимый API.

## Что это

Простой чат-клиент, который подключается к локальному серверу LLM (например, Ollama, vLLM, LM Studio, llama.cpp) по протоколу OpenAI и ведёт диалог с моделью, сохраняя контекст беседы.

Поддерживает любые модели, которые предоставляют OpenAI-совместимый API: Qwen, Llama, Mistral и другие.

## Быстрый старт

### 1. Настройка конфигурации

Скопируйте шаблон конфигурации:

```bash
copy .env-public .env
```

Откройте файл `.env` и заполните три обязательных параметра:

| Параметр | Обязательный | Описание | Пример |
|---|---|---|---|
| `AI_API_KEY` | да | API-ключ для доступа к серверу. Если сервер не требует ключ — напишите любое значение, например `ollama` | `sk-your-key-here` |
| `AI_ENDPOINT` | да | URL вашего AI-сервера с путём к `/v1`. Обязательно с `http://` или `https://` | `http://localhost:8080/v1` |
| `AI_MODEL_NAME` | да | Имя модели, которая запущена на сервере | `unsloth/Qwen3.6-35B-A3B-MTP-GGUF` |

Дополнительные параметры — необязательные, при отсутствии берутся значения по умолчанию:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `AI_MAX_HISTORY_MESSAGES` | `50` | Сколько последних реплик диалога (пар «вопрос + ответ») держать в контексте |
| `AI_REQUEST_TIMEOUT_SECONDS` | `300` | Таймаут одного запроса к модели, в секундах |

**Файл `.env` не попадает в git** — он создан специально для ваших локальных настроек и хранит их в секрете.

### 2. Проверка настройки

Перед первым запуском прогоните тесты — они проверяют, что настройки заполнены верно (из каталога проекта):

```powershell
dotnet test QwenAnswers.Tests\QwenAnswers.Tests\QwenAnswers.Tests.csproj -m:1
```

`-m:1` отключает многонодовую сборку MSBuild: в окружениях с ограничением прав на процессы worker-ноды не стартуют, и сборка падает без внятной ошибки.

Что проверяется:

| Категория | Что проверяет | Нужен `.env` |
|---|---|---|
| Обычные тесты | Логика: разбор `.env`, валидация, история, консольный цикл | нет |
| `Category=Architecture` | Договорённости репозитория: шаблон, `.gitignore`, README, сборка | нет |
| `Category=Readiness` | **Ваш** `.env` существует и заполнен корректно | да |
| `Category=Live` | Реальные запросы к запущенной модели | да + флаг |

`Category=Readiness` падает, если `.env` отсутствует или заполнен неверно — это и есть проверка настройки. В сообщении об ошибке будет указано, что именно поправить.

Чтобы прогнать только проверку настройки:

```powershell
dotnet test QwenAnswers.Tests\QwenAnswers.Tests\QwenAnswers.Tests.csproj -m:1 --filter "Category=Readiness"
```

Чтобы исключить её (например, в CI без модели):

```powershell
dotnet test QwenAnswers.Tests\QwenAnswers.Tests\QwenAnswers.Tests.csproj -m:1 --filter "Category!=Readiness&Category!=Live"
```

### 3. Живые тесты против модели

Тесты категории `Live` по умолчанию пропускаются. Чтобы они выполнились, запустите модель и включите флаг `AI_RUN_LIVE_TESTS=1` — в окружении или прямо в `.env`:

```powershell
$env:AI_RUN_LIVE_TESTS = "1"
dotnet test QwenAnswers.Tests\QwenAnswers.Tests\QwenAnswers.Tests.csproj -m:1 --filter "Category=Live"
```

Они проверяют, что сервер отвечает, что в списке моделей есть ваша `AI_MODEL_NAME` и что диалог действительно проходит через `ChatSession`.

### 4. Запуск

```bash
dotnet run
```

### 5. Использование

Введите сообщение и нажмите Enter. Во время ожидания ответа можно прервать запрос клавишей `Esc`. Для выхода введите `exit` или `quit`.

```
Чат с AI. Введите 'exit' для выхода.

Вы: Привет, как дела?
AI: Привет! Я здесь, готов помогать. Чем могу быть полезен?

Вы:
```

## Структура файлов

| Файл | Назначение |
|---|---|
| `.env` | **Ваши** секретные настройки (не коммитится в git) |
| `.env-public` | Шаблон с пустыми значениями — для копирования и ознакомления |
| `.gitignore` | Правила, исключающие `.env` из git |
| `Program.cs` | Точка входа: загрузка `.env`, валидация, запуск цикла |
| `Config/` | Чтение `.env`, модель настроек, имена ключей, валидация |
| `Chat/` | История диалога, сессия чата, консольный цикл, сборка клиента |
| `ConsoleAbstraction/` | Абстракция консоли (нужна для тестируемости) |
| `QwenAnswers.Tests/` | Тесты (unit / integration / architecture) |
| `QwenAnswers.csproj` | Проект .NET 10.0 |
| `README.md` | Этот файл |

## Технические детали

- **.NET 10.0**, C# последний
- **Microsoft.Extensions.AI** — абстракция над AI-клиентами
- **OpenAI** SDK — для совместимости с OpenAI-протоколом
- Простой парсер `.env` без внешних зависимостей
- Контекст диалога сохраняется в памяти (список сообщений, не более `AI_MAX_HISTORY_MESSAGES` реплик)
- System-подсказка и лимиты задаются в `Chat/ChatSessionFactory.cs`

## Troubleshooting

**"Ошибка: файл '.env' не найден"** — скопируйте `.env-public` в `.env` и заполните данные.

**"Ошибка: не заполнено поле AI_API_KEY в .env."** — проверьте, что все три обязательных параметра (`AI_API_KEY`, `AI_ENDPOINT`, `AI_MODEL_NAME`) имеют непустые значения. Такие ошибки выводятся списком, сразу по всем незаполненным полям.

**"Ошибка: AI_ENDPOINT должен начинаться с http:// или https://"** — в `AI_ENDPOINT` забыта схема. Правильно: `http://localhost:8080/v1`, неправильно: `localhost:8080/v1`.

**"Ошибка: AI_ENDPOINT не является валидным URI"** — проверьте, что значение целиком является URL, например `http://localhost:8080/v1`.

**"Connection refused"** — убедитесь что AI-сервер запущен и доступен по указанному `AI_ENDPOINT`.

**"Ошибка: ... 404"** — проверьте `AI_MODEL_NAME`: такого имени нет на сервере. Список моделей обычно доступен по адресу `<AI_ENDPOINT>/models`.
