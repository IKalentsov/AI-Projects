# Issue tracker: локальные markdown-тикеты

Задачи и спецификации WeatherBot живут markdown-файлами в `.scratch/` **корня проекта**
(`projects/WeatherBot`).

Внешний трекер не используется: `gh` CLI в среде не установлен, а обращение к GitHub Issues
без него невозможно. Смена трекера — отдельное решение пользователя, см. «Смена трекера».

## Соглашения

- Одна фича — один каталог: `.scratch/<feature-slug>/`
- Спецификация — `.scratch/<feature-slug>/spec.md`
- Тикеты — по одному файлу на тикет: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`,
  нумерация с `01`, blockers-first. Сводного файла со всеми тикетами не бывает.
- Состояние — строка `Status:` в начале файла тикета (значения — `triage-labels.md`).
- `Blocked by: NN, NN` — рядом с началом файла. Тикет разблокирован, когда все перечисленные
  в нём закрыты.
- История и комментарии дописываются в конец файла под заголовком `## Comments`.

## Когда скилл говорит «publish to the issue tracker»

Создать файл в `.scratch/<feature-slug>/` (каталог создаётся при необходимости).

## Когда скилл говорит «fetch the relevant ticket»

Прочитать файл по указанному пути. Пользователь обычно передаёт путь или номер тикета.

## Смена трекера

GitHub Issues — рабочая альтернатива: remote проекта указывает на GitHub. Переход требует
установки и авторизации `gh` CLI (работа пользователя, нужен доступ в сеть). После этого этот
файл переписывается под GitHub по шаблону `issue-tracker-github.md`, а `.scratch/` перестаёт
быть источником тикетов.
