# WeatherBot

Telegram-бот, который каждые 30 минут отправляет в канал сводку о текущей погоде в заданном
городе (по умолчанию Москва). Данные — HTTP API **Open-Meteo**, ключ не требуется.
Управление — через REST API; интерактивная документация — Scalar.

- **Стек**: .NET 10, C# (последняя версия), Clean Architecture (5 проектов).
- **База данных**: не используется. **Docker**: не используется.
- **Хостинг**: локальный компьютер пользователя.
- **Фронтенд**: не входит в текущий этап — планируется отдельный SPA на React поверх этого REST API.
- **Погодные данные**: [Open-Meteo](https://open-meteo.com) — лицензия CC-BY 4.0, атрибуция обязательна.

## Сборка и запуск

```bash
# из backend/WeatherBot
dotnet restore
dotnet build WeatherBot.slnx -c Debug
dotnet run --project src/WeatherBot.Web
```

Адрес запуска — `http://localhost:5157` (`src/WeatherBot.Web/Properties/launchSettings.json`),
документация API — `http://localhost:5157/scalar/v1`.

Проверить связку «бот → канал», не обращаясь к API погоды:

```bash
curl -X POST http://localhost:5157/api/bot/send-test
```

Реальные значения лежат в `src/WeatherBot.Web/appsettings.Development.json`
(`Telegram:BotToken` уже заполнен, `Telegram:ChannelId` — канал «Погода»).
**Этот файл закрыт от git** правилом в `backend/.gitignore` — секреты в репозиторий не попадают.
Ключа погоды не требуется: Open-Meteo работает без авторизации. Бот должен быть
администратором канала с правом «Публикация сообщений».

## API

| Метод | Маршрут | Что делает |
|-------|---------|-----------|
| POST | `/api/bot/start` | запустить периодическую отправку (409, если уже запущен) |
| POST | `/api/bot/stop` | остановить (409, если уже остановлен) |
| POST | `/api/bot/send-now` | отправить сводку немедленно (502, если не удалось) |
| POST | `/api/bot/send-test` | диагностика: тестовое сообщение в канал, без обращения к API погоды |
| GET | `/api/bot/status` | состояние бота, время последней и следующей отправки |
| GET | `/api/bot/logs?count=20` | последние записи журнала |
| GET | `/health` | проверка «сервис жив» |

Пример:

```bash
curl -X POST http://localhost:5157/api/bot/start
curl http://localhost:5157/api/bot/status
```

## Ограничения текущего этапа

- Тестовый контур заведён: `tests/WeatherBot.UnitTests` (68 тестов маппера и форматтера) и
  `tests/WeatherBot.ArchitectureTests` (наполняется тикетами `01`–`02` фичи `weather-provider`).
- Источник погоды — Open-Meteo, город — в настройках (`OpenMeteo:City`).
- Настройки только читаются: запись в `appsettings.json` из приложения не реализована.
- Интервал отправки применяется при старте; изменение на лету не подхватывается.

## Безопасность

- Секреты — только в `appsettings.Development.json` (**не коммитится**) либо в переменной
  окружения `Telegram__BotToken`. В `appsettings.json` — пустая заглушка.
- Токен маскируется в журналах и ответах API (`SecretMasker`); объект исключения
  в Telegram-клиенте не логируется, чтобы токен не утёк через URL запроса.
- Сервис слушает только `localhost:5157`, `AllowedHosts` ограничен `localhost;127.0.0.1`.
- **Аутентификации нет** — не выставлять сервис в общую сеть: любой, кто до него дотянется,
  сможет писать в канал.
- Токен, опубликованный в открытом виде, считается скомпрометированным — перевыпустить
  у @BotFather командой `/revoke`.
