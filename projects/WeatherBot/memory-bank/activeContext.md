## 3. Что сделано в прошлый прогон (2026-09-18)

Написан весь бэкенд по постановке. По ходу пришлось принять несколько решений:

1. **Структура проектов** приведена к постановке: `Core` → `Application`, `Web` остался один
   (вариант `WebUI` был лишним и удалён по указанию пользователя). `Contracts` сохранён
   по решению пользователя.
2. **Razor Pages не создавались** — пользователь подтвердил: UI будет на React отдельным этапом.
3. Настройки собраны в Domain (`*Settings` + `SectionName`), дубли `*Options` из постановки не заводились.
4. **Запись настроек отложена** — настройки только читаются из `appsettings.json`.

Три ошибки сборки, найденные и исправленные:

- `CS0234`: папка `Infrastructure/Telegram` ломала `using Telegram.Bot` → переименована в `Messaging`.
- `CA1031` и `CA2000` в фоновой задаче: пересоздание `PeriodicTimer` убрано (интервал читается
  один раз при старте), для перехвата исключений в цикле правило `CA1031` отключено.
- `S6960` («несколько ответственностей»): `logs` вынесен из `BotController` в `BotLogController` —
  правило группирует действия по используемым сервисам.

**Второй прогон (2026-09-18), подключение Telegram:**

- Токен бота записан в `appsettings.Development.json`; файл закрыт правилом
  `**/appsettings.Development.json` в `backend/.gitignore` (проверено `git check-ignore`).
  В коммитимом `appsettings.json` — пустые заглушки и `AllowedHosts: localhost;127.0.0.1`.
- `ChannelId` = `-1004293595218` (канал «Погода», `@kalentsov_pogoda`).
- Добавлен диагностический эндпоинт `POST /api/bot/send-test` — проверка канала без API погоды.
- Закрыта утечка секрета: `SecretMasker` очищает токен в текстах ошибок, а объект исключения
  в Telegram-клиенте больше не логируется (URL Bot API содержит токен). Логирование вынесено
  из `catch`-блока — это заодно сняло замечание `S6667` без подавления правила.
- user-secrets как хранилище **отклонены**: запись в `%APPDATA%` заблокирована песочницей,
  пользователь выбрал `appsettings.Development.json`.

**Аудит и раскладка (2026-09-21):**

## 6. Осторожно при работе с этим проектом

- **Хостинг — компьютер пользователя.** Docker не используется; приложение запускает
  пользователь, агент — только сборку.
- **Базы данных нет.** Не добавлять EF Core, Npgsql, Dapper и миграции.
- **Фронтенда нет и не должно быть в этом решении.** Никаких Razor Pages, `.cshtml`,
  wwwroot и статики — UI будет отдельным SPA на React.
- **Сеть из shell агента недоступна**: `dotnet restore` выполняет пользователь,
  агент собирает с `--no-restore`. Полные команды и ограничения среды — `WORKFLOW.md` §2.
- **`dotnet test` в песочнице падает** (запрет именованных каналов): тесты гоняются **прямым
  вызовом собранной сборки**, а сборка — только с `-m:1`.
- **Папку `Infrastructure/Messaging` не переименовывать в `Telegram`** — сломается `using Telegram.Bot`.
- **Эталон `DirectoryService` — только чтение** (глобальные правила `~/.dsh/AGENTS.md` §14).
