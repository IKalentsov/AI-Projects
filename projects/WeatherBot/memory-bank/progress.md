## 1. Что уже есть

- **5 проектов** в `src/`: Contracts, Domain, Application, Infrastructure, Web.
  Направление зависимостей — строго внутрь.
- **Погода**: провайдер Open-Meteo (HTTP/JSON, **без ключа**), маппинг значений API в домен,
  обработка кодов ответа, таймаута и ошибок. Платный источник погоды удаляется задачей
  `01-01`; до её выполнения в коде ещё стоит прежний провайдер.
- **Telegram**: `TelegramSender` (Long Polling не используется — бот только отправляет),
  `ParseMode.Markdown`, обработка `ApiRequestException` / `RequestException`.
- **Сообщение**: `WeatherMessageFormatter` — формат из постановки, время в МСК.
- **Расписание**: `WeatherBotBackgroundService` (`PeriodicTimer`), первый тик через полный
  интервал, пропуск итераций при остановленном боте, перехват исключений в цикле.
- **Состояние**: `BotStateManager` (Singleton, потокобезопасный) — `IsRunning`, `LastSentAt`,
  `NextTickAt`.
- **Журнал**: консоль (стандартный провайдер) + `InMemoryLogBuffer` на 100 записей
  через `InMemoryLoggerProvider`.
- **REST API**: `POST /api/bot/start`, `POST /api/bot/stop`, `POST /api/bot/send-now`,
  `POST /api/bot/send-test` (диагностика канала без API погоды), `GET /api/bot/status`,
  `GET /api/bot/logs`, `GET /health`; Scalar на `/scalar/v1`.
  `start`/`stop` возвращают 409 при неверном состоянии бота.
- **Конфигурация**: секции `Telegram`, `OpenMeteo`, `WeatherBot`; биндинг через
  `IOptionsMonitor<T>`. `ChannelId` = `-1004293595218` (канал «Погода»).
- **Секреты**: `Telegram:BotToken` — в `appsettings.Development.json`, файл закрыт
  правилом `**/appsettings.Development.json` в `backend/.gitignore`.
  `SecretMasker` очищает секреты в журналах и ответах API; объект исключения
  в Telegram-клиенте не логируется.
- **Харденинг**: сервис слушает только `localhost:5157`, `AllowedHosts: localhost;127.0.0.1`,
  документация API — только вне Production.
