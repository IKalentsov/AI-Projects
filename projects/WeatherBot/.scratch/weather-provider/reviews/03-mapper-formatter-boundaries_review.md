### Проверка «тесты падали бы до правки»

Воспроизвести падение откатом нельзя (git-операции — не моя зона), поэтому я посчитал старые
выражения на тех же входах вручную. Важно: в C# `(int)` **усекает**, а PowerShell `[int]`
округляет — с учётом этого:

| Вход | Старое выражение давало | Тест ожидает | Падал бы? |
|---|---|---|---|
| смещение `+5:30` | `UTC+5` (`(int)5.5`) | `UTC+5:30` | да ✅ |
| смещение `+5:45` | `UTC+5` (`(int)5.75`) | `UTC+5:45` | да ✅ |
| смещение `+5:00` | `UTC+5` | `UTC+5` | нет (это защита от `:00`, а не регрессия) |
| `precipitation = -1.0` | `VeryHeavy` (ветка `_`) | `None` | да ✅ |
| влажность `72.6` | `72` (`(int)72.6`) | `73` | да ✅ |
| влажность `72.4` | `72` | `72` | нет (страховка снизу) |

Итог: четыре регрессионных теста из шести действительно ловили дефекты, два оставшихся — границы
поведения. Формулировка отчёта «4 из 4 падали» этому соответствует.

## Разбор правок

1. **Форматтер.** `sign` теперь `+`/`-`, минуты выводятся через `:D2` только при ненулевом
   остатке. Для зон с нулевыми минутами поведение не изменилось (`UTC+3`, `UTC-4` — как было),
   то есть правка касается ровно дефекта и ничего больше. Отрицательные зоны с минутами
   (например `-5:30`) считаются через `Math.Abs` — арифметика верна.
2. **Маппер.** `0 =>` заменено на `<= 0 =>`. Поведение для нуля и положительных значений
   идентично прежнему, изменилась только ветка отрицательных.
3. **Провайдер.** Усечение заменено округлением. Заявленное в отчёте «согласовано с существующим
   `ToPressureMmHg`» — **проверено и верно**: там тоже `Math.Round(..., MidpointRounding.AwayFromZero)`.
