# 07: Координаты уходят в Open-Meteo в культуре процесса

**What to build:** Запрос к Open-Meteo формируется одинаково независимо от культуры процесса.
Сейчас на машине с `ru-RU` в API уходит `latitude=55,7558&longitude=37,6173` — Open-Meteo отвечает
`400`, и погода не приходит **ни по кнопке `send-now`, ни по расписанию**. После тикета живой
`POST /api/bot/send-now` возвращает `200`, а в канал уходит сводка.

Подтверждено на живом запуске 2026-09-22: `502`, тело `{"success":false,"isRunning":true,
"message":"Open-Meteo вернула код 400"}`. Тестовое сообщение в Telegram при этом доходит — то есть
Telegram настроен, ломается именно запрос погоды.

**Причина.** В `OpenMeteoWeatherProvider.BuildUrl` координаты подставляются в интерполяцию строки:
`$"?latitude={settings.Latitude}"`. Интерполяция форматирует `double` в **текущей культуре**
процесса; культура здесь `ru-RU`. В `WeatherBot.Web` культура нигде не переопределяется,
`appsettings.json` содержит `Latitude: 55.7558`, `Longitude: 37.6173`.

сессии, без передачи Qwen. **Отклонение от процесса:** исполнитель и ревьюер — одно лицо,
независимого ревью этой правки не было. Отчёт — `reports/07-openmeteo-url-culture_report.md`.
