## 3. Контекст для исполнителя

### Среда

- Каталог команд — `backend/WeatherBot`.
- `-m:1` обязателен и для `restore`, и для `build`: без него команда завершается кодом 1,
  не напечатав ни строки, а сводка врёт — `Ошибок: 0`.
- `-p:NuGetAudit=false` обязателен: без сети `NU1900` становится ошибкой (`TreatWarningsAsErrors`).
- `dotnet test` на Microsoft.Testing.Platform падает на именованном канале — тесты запускаются
  **прямым вызовом собранной сборки**, как в таблице §1.
- Пакеты уже в локальном кэше; новые пакеты не добавляются (`Directory.Packages.props` не трогать).

### Атрибуты xUnit v3 — не выдумывать

| Ложное | Правильное |
|---|---|
| `[fact]`, `[theory]` | **`[Fact]`**, **`[Theory]`** |
| `[case(1, 2.5)]` | **`[InlineData(1, 2.5)]`** — `[case]` не существует |
| `using Xunit.v3;` | **`using Xunit;`** |
| — | для `Should()` нужен **`using AwesomeAssertions;`** |

Сборка ругается — читать текст ошибки, а не угадывать имена. Образец рабочего кода на том же
стеке — `projects/marketsniper-mvp/backend/tests/`.

### Границы правки

- Тесты пишутся только в `tests/**`. Продакшн-код `src/**` в тикетах `01` и `02` не меняется;
  в тикете `03` меняются ровно три указанные строки.
- **Исключение (внесено ревью 2026-09-22).** Если тест вскрывает дефект продакшн-кода, правка
  `src` разрешена: минимальная, по существу дефекта, с обоснованием в отчёте и отдельным пунктом
  в критериях. Молчаливая правка не принимается. Так был исправлен разбор ответа Open-Meteo
  (находка `F-15`).
- Не трогаются: `*.csproj`, `tests/Directory.Build.props`, `Directory.Packages.props`,
  `WeatherBot.slnx`, `global.json`, `ARCHITECTURE.md`, `AGENTS.md`, `WORKFLOW.md`, `README.md`,
  `docs/agents/**`, `spec.md` и файлы тикетов.
- **Массовые замены исходников скриптами и regex-проходами запрещены** — только `write` / `edit`
  поштучно. Это правило оплачено провалом 2026-09-21: одна команда `-replace ... | Set-Content`
  превратила девять файлов в мусор, сборка дала 732 ошибки.
- **Сборка после каждого нового файла**, а не один раз в конце.
- Не более **3 попыток** на один блокер; дальше — стоп и честный отчёт.

### Скиллы

Перед работой **просмотри доступные тебе скиллы и примени один подходящий** к задаче — выбирает
исполнитель, перечислять их в тикете не нужно. Если архитектор назвал конкретный скилл, применяется
он. Отчитываться о применении не требуется. Один скилл на задачу: больше — трата контекста.
Скиллы, скрытые от модели (`disable-model-invocation`), запускает только человек командой `/имя`.

## 4. Детали по тикетам

Раздел существует потому, что исполнитель — локальная junior-модель, а не полноценный агент:
тикеты описывают поведение, а точные швы и границы собраны здесь.

### Тикет 01 — провайдер, оркестрация, DI

Файлы: `tests/WeatherBot.UnitTests/OpenMeteoWeatherProviderTests.cs`,
`tests/WeatherBot.UnitTests/WeatherDigestServiceTests.cs`,
`tests/WeatherBot.ArchitectureTests/DiCompositionTests.cs`.

Швы:

- `IWeatherProvider` — HTTP подменяется заглушкой `HttpMessageHandler`; реальная сеть запрещена.
  `OpenMeteoWeatherProvider` берёт клиент из `IHttpClientFactory`, в тесте подставляется заглушка
  фабрики, отдающая `HttpClient` с этим обработчиком.
- `WeatherDigestService` принимает `IWeatherProvider`, `IWeatherFormatter`, `ITelegramSender`,
  `IBotStateManager` — все четыре подменяются через NSubstitute.
- `DiCompositionTests` собирает настоящую коллекцию сервисов и проверяет резолв.

Покрыть по провайдеру: успешный разбор эталонного ответа (включая `ObservedAt` со смещением из
`utc_offset_seconds` и давление в мм рт.ст.); не-200 → `Result.Failure`; таймаут
(`TaskCanceledException` без отмены токена) → `Result.Failure`; битый JSON → `Result.Failure`;
ответ без блока `current` → `Result.Failure`; неразбираемое или отсутствующее `time` →
`Result.Failure`, не исключение; в запросе присутствуют `wind_speed_unit=ms` и `timezone=auto`;
ни один путь не выбрасывает исключение наружу.

Покрыть по оркестратору: успех (погода → текст → отправка → `MarkSent`); погода не получена →
отправки нет, результат — ошибка провайдера; Telegram отклонил → ошибка отправки, `MarkSent`
**не** вызван; одновременные вызовы не дают наложения отправок.

Покрыть по DI: собрать `ServiceCollection`, вызвать `AddInfrastructure` с конфигурацией, собрать
`ServiceProvider` и убедиться, что резолвятся `IWeatherProvider`, `IWeatherFormatter`,
`ITelegramSender`, `IBotStateManager`, `ILogBuffer`, `IHttpClientFactory`.

Почему DI обязателен: в `01-01` `IHttpClientFactory` остался незарегистрированным при полностью
зелёной сборке — компилятор такую ошибку не ловит, её видно только при резолве.

### Тикет 02 — состояние, буфер, маскировка, слои

Файлы: `tests/WeatherBot.UnitTests/BotStateManagerTests.cs`,
`tests/WeatherBot.UnitTests/InMemoryLogBufferTests.cs`,
`tests/WeatherBot.UnitTests/SecretMaskerTests.cs`,
`tests/WeatherBot.ArchitectureTests/LayerDependenciesTests.cs`.

`BotStateManager` (Singleton, потокобезопасный): стартовое состояние — не запущен, `LastSentAt`
и `NextTickAt` пусты; `Start()` / `Stop()` меняют `IsRunning`, `Stop()` обнуляет `NextTickAt`;
`MarkSent` / `MarkNextTick` проставляют значения, `MarkNextTick(null)` обнуляет; параллельные
вызовы из нескольких потоков не бросают исключений и не теряют состояние.

`InMemoryLogBuffer` (ёмкость `Capacity` = 100): хранится не больше `Capacity`, при переполнении
вытесняется самая старая запись; `GetRecent(n)` — последние `n` в хронологическом порядке;
`GetRecent(0)` и отрицательное значение → пустой список; `Add` с пустой строкой отклоняется.

`SecretMasker` (`internal static`): секрет встречается один раз и несколько раз → заменены все
вхождения; пустой или `null` секрет → текст без изменений; `null` или пустой текст → пустая строка.

`LayerDependenciesTests` проверяет **фактическое использование** типов между пятью проектами
`src` (уточнено ревью 2026-09-22): `Domain` не зависит ни от одного проекта решения;
`Application` зависит только от `Domain`; `Infrastructure` не зависит от `Web`; `Contracts` не
использует типы других проектов; `Web` не использует типы `Domain` напрямую. Оговорка, которую
обязан объяснить сам тест: `Assembly.GetReferencedAssemblies()` видит только использованные
ссылки, а объявленные в `.csproj` и неиспользуемые (`Contracts → Domain` — `F-10`,
`Web → Domain` — `F-16`) в метаданных отсутствуют и архитектурным тестом не ловятся; это предмет
реестра находок, а не теста. Реализация — запасной вариант через
`Assembly.GetReferencedAssemblies()` (допустим) либо `TngTech.ArchUnitNET` (пакеты подключены),
архитектура собирается один раз в статическом поле. Обязательна **канарейка**: тест утверждает,
что разрешённая зависимость видна (`Application → Domain`, `Infrastructure → Application`), иначе
набор правил может «пройти» молча при неудачной загрузке сборок. **Проверка обязана падать при
нарушении** — иначе она бесполезна.

### Тикет 03 — границы маппера и форматтера (`F-14`)

Три дефекта, отложенных ревью `01-01` и не попавших ни в одну постановку:

1. Смещение часового пояса печатается как `(int)offset.TotalHours` — зоны `:30`/`:45` теряют
   минуты (например `UTC+5:45` печатается как `UTC+5`). Ожидаемое поведение: смещение
   отображается с минутами, если они не равны нулю, и без них, если равны.
2. Отрицательная `precipitation` не попадает ни в одну ветку `switch` интенсивности и уходит
   в `_` → `VeryHeavy`. Ожидаемое поведение: отрицательное значение трактуется как отсутствие
   осадков (`None`).
3. Влажность берётся как `(int)c.RelativeHumidity2m` — усечение вместо округления.
   Ожидаемое поведение: значение округляется, а не отбрасывает дробную часть.

Каждая правка — отдельный тест, падающий до неё. Границы проверяются по обе стороны порога.

## 5. Приёмка (общая для всех тикетов)

Каталог — `backend/WeatherBot`; вывод команд приводится **дословно**.

```bash
dotnet build WeatherBot.slnx -c Debug -m:1 --no-restore -p:NuGetAudit=false
dotnet tests/WeatherBot.UnitTests/bin/Debug/net10.0/WeatherBot.UnitTests.dll
dotnet tests/WeatherBot.ArchitectureTests/bin/Debug/net10.0/WeatherBot.ArchitectureTests.dll
```

- Сборка: `Ошибок: 0`, `Предупреждений: 0`.
- Обе тестовые сборки: `сбой: 0` и ненулевое число тестов; число пройденных приведено
  и включает тесты предыдущих тикетов (после `01` их не меньше 68).
- Реальная сеть в тестах не используется. Проект не запускается — его запускает только пользователь.
- **Правка `src` — сравнением с базовым состоянием**, а не глаголом `git status`. В отчёт идёт
  **полный** вывод команды с указанием каталога, из которого она запущена. Пустой вывод сам по себе
  ничего не доказывает: он одинаково получается и когда правок нет, и когда путь не разрешается
  из текущего каталога — на этом исполнитель оступился в тикете `04`. Ожидаемое: только принятые
  ранее файлы (`WeatherBot.Infrastructure.csproj` из `01-01`, `OpenMeteoContracts.cs` из тикета `01`)
  плюс — по исключению из §3 — файлы, правка которых необходима для прохождения теста и объявлена
  в отчёте.
- Секретов в коде и отчёте нет; `appsettings.Development.json` не тронут.

## 6. Отчёт исполнителя

Отчёт — файл `reports/<NN>-<slug>_report.md` рядом с тикетом, обязательные разделы: что сделано
(файлы с полными путями), команды и дословный вывод, отклонения и замеченное «заодно», что
не проверено и почему. «Готово» без вывода команд не принимается. Не получилось — написать прямо:
что не вышло, сколько было попыток, что пробовал, какие ошибки получил.

## 7. Что сознательно не делается

- Новые пакеты, `IntegrationTests`, БД, ORM, Docker, фронтенд-код — вне области решения.
- Коммиты и любые git-операции, меняющие состояние репозитория, — зона пользователя.
- Тикеты не расширяются «заодно»: найденное постороннее идёт в отчёт, а не в код.
