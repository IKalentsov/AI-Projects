# Project AGENTS.md — WeatherBot

> Проектные правила. Глобальные (роли, цикл задачи, DoD, язык, git) — в `~/.dsh/AGENTS.md`.
> Этот файл дополняет глобальный и имеет приоритет для текущего проекта.
> Ни один из них не отменяет прямые указания пользователя.

## 1. Проект

- **WeatherBot** — Telegram-бот: каждые N минут (по умолчанию 30) отправляет в канал
  сводку о текущей погоде в заданном городе (по умолчанию Москва). Данные — HTTP API
  **Open-Meteo**, ключ не требуется.
- Архитектура: Clean Architecture, 5 проектов (.NET 10, последняя версия C#).
- **Базы данных нет** и не планируется. EF Core, Npgsql, Dapper, миграции не добавлять.
- **Фронтенда в решении нет.** UI планируется отдельным SPA на React поверх текущего REST API.
  Razor Pages, MVC-представления и статические страницы не добавлять.
- **Хостинг — компьютер пользователя.** Docker и контейнеры не используются.
- API-документация: Scalar (`/scalar/v1`).
- Состояние проекта — `memory-bank/`; архитектура — `ARCHITECTURE.md`. Оба файла — в корне проекта.

## 3. Паттерны (обязательные)

- **Result Pattern** (`CSharpFunctionalExtensions`): ожидаемые бизнес-ошибки — значениями
  `Result` / `Result<T>`, а не исключениями.
- **Ошибки не покидают инфраструктуру**: реализации `ITelegramSender` и `IWeatherProvider`
  ловят конкретные исключения и возвращают `Result.Failure(...)`.
- **Абстракции — в Application, реализации — в Infrastructure.**
- **Domain — только BCL**: ни одного пакета, ни одной ссылки на другие проекты.
- **Секреты** — только из конфигурации; пустой токен/ключ не должен ронять приложение.
- MediatR, AutoMapper, FluentValidation, Scrutor **не используются**.

## 4. Сборка и запуск

Каталог — `backend/WeatherBot`. Полные команды и таблица ограничений среды — `WORKFLOW.md` §2.

```bash
dotnet restore WeatherBot.slnx -m:1 -p:NuGetAudit=false    # офлайн из кэша; доступно агенту
dotnet build WeatherBot.slnx -c Debug -m:1 --no-restore    # сборка (агент)
dotnet tests/WeatherBot.UnitTests/bin/Debug/net10.0/WeatherBot.UnitTests.dll   # тесты (агент)
dotnet run --project src/WeatherBot.Web                    # запуск — ТОЛЬКО пользователь
```

- **Агент проект НЕ запускает** — только сборку, restore и тесты.
- **`-m:1` обязателен и для `restore`, и для `build`**: без него команда завершается кодом 1,
  не напечатав ни строки, а сводка врёт — `Ошибок: 0`.
- **`dotnet test` не использовать**: в песочнице падает на именованных каналах. Тесты
  запускаются **прямым вызовом собранной сборки**, как в примере выше.
- **`-p:NuGetAudit=false` обязателен**, иначе без сети `NU1900` станет ошибкой.
- **Restore доступен агенту** офлайн из локального кэша; пользователь нужен только за пакетами,
  которых в кэше нет.
- Стек тестов: xUnit v3 через Microsoft.Testing.Platform; проекты
  `tests/WeatherBot.UnitTests` и `tests/WeatherBot.ArchitectureTests`.

## 5. Обязанности по архитектуре

- Любое изменение структуры, контрактов, API, стека, пакетов — сразу актуализировать
  `ARCHITECTURE.md`.
- Если в `ARCHITECTURE.md` нет раздела про тестирование — добавить.
- Расхождения между кодом и `memory-bank/` устраняются в том же прогоне (приоритет — у кода).
- **Новое отключение правила анализатора — только с согласия пользователя**; запись в
  `backend/.globalconfig` сопровождается комментарием с причиной. Реестр — `ARCHITECTURE.md`.

## 6. Скиллы

В проекте скиллы **не хранятся**: общие лежат в глобальном корне `~/.dsh/skills`, видны во всех
проектах и подгружаются по требованию (не раздувают каждую сессию).

**Процессные скиллы** — использовать по назначению:

- `task-authoring` — постановка микро-задачи для исполнителя;
- `code-review` — ревью задачи по факту кода и прогонов;
- `architecture-drift-check` — сверка кода с `ARCHITECTURE.md`;
- `systematic-debugging` — поиск root cause.

**Скиллы по сборке и тестам — официальные, из маркета DSH:** `run-tests`,
`migrate-vstest-to-mtp`, `scaffold-dotnet-test-project`, `directory-build-organization`.
**Загружать их перед сборкой, прогоном тестов и заведением тестовых проектов**, а не
пересказывать здесь. Новый скилл заводить только при реальной потребности — и только убедившись,
что официального нет.

**Команды проверки и ограничения среды живут только в `WORKFLOW.md` §2** — один раз;
постановки ссылаются туда, а не дублируют.

## 7. Владение файлами и порядок изменений

- **Роли**: пользователь — владелец продукта и главный разработчик (принимает решения).
  DeepSeek V4.x Flash — архитектор, ревьювер и разработчик. Qwen3.6-MTP — исполнитель
  микро-задач по подробным постановкам.
- **Архитектуру и `.md`-артефакты меняет только архитектор**: `ARCHITECTURE.md`, постановки,
  review, fixes, `WORKFLOW.md`, `ai-tasks/`, `.dsh/AGENTS.md`, `memory-bank/`, `README.md`.
  Исполнитель — только read (кроме кода проекта и своего `.report.md`).
- **Порядок изменения архитектуры**: пользователь подтверждает, что задача затрагивает
  архитектуру → архитектор правит `ARCHITECTURE.md` ДО старта исполнителя → затем постановка.
- **Постановка содержит маркер** `Требует изменения архитектуры: да/нет`.
- **Нарушение исполнителя на ревью**: проверяется git; расхождение фиксируется в отчёте,
  решение (откат / согласовать) — за пользователем.

## 8. Git — зона пользователя

Все операции, меняющие состояние репозитория, выполняет пользователь
(перечень — `~/.dsh/AGENTS.md` §11). Агенту разрешено только чтение: `git status`, `git diff`,
`git log`, `git show`, `git blame`. Проект живёт в монорепозитории `AI-Projects`,
рабочая ветка — `develop`.

## 9. Красные линии

- Коммитить секреты, токены, ключи. Реальные значения — **только** в `appsettings.Development.json`
  (закрыт правилом `**/appsettings.Development.json` в `backend/.gitignore`) или в переменных окружения.
  В `appsettings.json` держать пустые заглушки.
- Логировать или возвращать в ответе API токен/ключ. Секреты проходят через `SecretMasker`;
  объект исключения в Telegram-клиенте в журнал не передаётся (URL Bot API содержит токен).
- Выставлять сервис в общую сеть. Слушать только `localhost`; аутентификации в проекте нет.
- Добавлять базу данных, ORM или миграции.
- Добавлять Razor Pages, MVC-представления, статические страницы или любой фронтенд-код.
- Выполнять git-операции вместо пользователя.
- Менять версии пакетов вне `backend/Directory.Packages.props`.
- Отключать анализаторы или `TreatWarningsAsErrors` без согласия пользователя.
- Запускать приложение или контейнеры вместо пользователя.
- Расширять объём задачи «заодно».
