## 2. Команды

Каталог — `backend/WeatherBot`.

```bash
dotnet restore WeatherBot.slnx -m:1 -p:NuGetAudit=false      # офлайн из локального кэша
dotnet build WeatherBot.slnx -c Debug -m:1 --no-restore -p:NuGetAudit=false   # сборка
dotnet tests/WeatherBot.UnitTests/bin/Debug/net10.0/WeatherBot.UnitTests.dll
dotnet tests/WeatherBot.ArchitectureTests/bin/Debug/net10.0/WeatherBot.ArchitectureTests.dll
dotnet run --project src/WeatherBot.Web                       # запуск — ТОЛЬКО пользователь
```

**Ограничения песочницы агента** — коротко (проверено прогонами 2026-09-21):

- `-m:1` обязателен **и для `restore`, и для `build`**: без него команда завершается кодом 1,
  не напечатав ни строки, а сводка врёт — `Ошибок: 0`;
- `-p:NuGetAudit=false` обязателен: без сети `NU1900` становится ошибкой из-за `TreatWarningsAsErrors`;
- `dotnet test` на MTP падает на именованном канале — тесты запускаются **прямым вызовом
  собранной сборки**;
- **restore доступен агенту** (офлайн из кэша) и пользователю. Пользователь нужен только за
  пакетами, которых в локальном кэше нет.

**Как выглядит, если про это забыть** (одинаково для любого .NET-проекта в харнессе):

- команда вернула `Ошибок: 0`, но код 1 и пустой вывод → не хватает `-m:1`;
- `NU1900` в restore или сборке → не хватает `-p:NuGetAudit=false`;
- тест-хост MTP упал на `NamedPipeClientStream` → запускать собранную сборку напрямую,
  а не `dotnet test`.

**Это обходы только для агента.** На машине пользователя и в CI работают штатные
`dotnet restore` / `dotnet build` / `dotnet test`.

- Тестовые проекты создаются задачей `01-02`; до неё прогонять нечего.

## 3. Стек и запреты проекта

- .NET 10, последняя версия C#, Clean Architecture (5 проектов), Result Pattern.
- **БД нет** — EF Core, Npgsql, Dapper, миграции не добавляются.
- **Docker не используется** — хостинг локальный, на компьютере пользователя.
- **Фронтенда в решении нет** — UI планируется отдельным SPA на React поверх REST API.
- Версии пакетов — только в `backend/Directory.Packages.props`.
- Анализаторы: `TreatWarningsAsErrors=true`. Новое отключение правила — только с согласия
  пользователя, с комментарием-причиной в `backend/.globalconfig` и записью в `ARCHITECTURE.md`.

## 5. Git-конвенции проекта

- **Git-операции выполняет только пользователь.** Агенту разрешено чтение: `git status`,
  `git diff`, `git log`, `git show`, `git blame`. Ветку создаёт и push делает пользователь.
- Ветки: `develop` — рабочая; `feature/<краткое-имя>`, `fix/<краткое-имя>`, `chore/<...>`.
- Коммиты — Conventional Commits: `feat(backend): …`, `fix(web): …`, `test(core): …`,
  `docs: …`, `chore: …`. Тип и область — английские, текст — русский.
- В теле коммита — «почему», а не пересказ диффа. Трейлеры `Refs:` (постановка в `ai-tasks/`)
  и `Not tested:` (что не проверялось) — по необходимости.
- Не коммитить сгенерированное (`bin/`, `obj/`, `.vs/`) и секреты:
  `appsettings.Development.json` закрыт правилом в `backend/.gitignore`.
- Текст коммита агент готовит по фактическому `git status` / `git diff` (глобальные правила §11),
  но сам не выполняет ни `add`, ни `commit`, ни `push`.
